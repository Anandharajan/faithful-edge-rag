# Contributing

Contributions should preserve the research objective: a reproducible open-source edge-cloud RAG system evaluated under distributed, private, and conflicting evidence conditions.

## Development Flow

1. Open or select an issue.
2. Create a feature branch.
3. Keep changes scoped and tested.
4. Run `ruff check .`, `mypy src`, and `pytest`.
5. Open a pull request with implementation notes and verification output.

## Research Claims

Any claim of improvement must include:

- Dataset or scenario name.
- Baseline condition.
- Model and embedding checkpoint.
- Hardware profile.
- Metric definition.
- Raw result or reproducible command.
